# Observatory integration

Shared collector/dashboard: [Pulseboard #15](https://github.com/Chris0Jeky/Pulseboard/pull/15), source commit `35b929dbe9033f357548107dcf28aa29f980d4db` on Pulseboard `main`.

The build incorporates the local adapter into the application bundle before minification, content hashing and service-worker manifest generation. The small boot diagnostics script remains unchanged. No post-build artifact injection, remote CDN or save-schema change is introduced. The artifact is now generated with the registered endpoint `https://pulseboard-observatory.commit-atlas.workers.dev/v1/collect/alibi`, and collection is enabled on that collector, so this is the activated pilot rather than an inert install. Nothing is sent until the player ticks the consent box. The adapter also requires `ALIBI_CONFIG.standalone === false`, so a standalone export remains silent even when hosted on the primary origin, and it stays silent under Global Privacy Control, Do Not Track or off the public origin. The document policy adds the collector origin to `connect-src` only; `tools/build.cjs` holds it as `OBSERVATORY_ORIGIN` next to the delivery origins and feeds one string to both the `index.html` meta tag and `dist/_headers`.

The consent control the player sees is a native `details` block titled **Usage sharing**, containing: "Optional: share a small set of action counts with pulseboard-observatory.commit-atlas.workers.dev. No document text, filenames, form values or browsing history is sent. Raw events expire after 14 days. Your choice lasts 90 days on this browser." and the checkbox label "Share basic usage for this site". Unticking it stops future collection; the choice is stored per browser for 90 days.

Run `npm run build`, then `node observatory/check.mjs`: it verifies the artifact hash against `observatory.lock.json`, the exact endpoint, the absence of server-only constants, the public-origin standalone rejection, and that the emitted `dist/_headers` and `index.html` policy list the collector origin in `connect-src`. Rebuild and run existing tests, formatting, distribution validation, service-worker update checks and hosted QA before approval. Shared kit: 58 local tests passed, including the standalone guard. The initial boot integration exceeded the existing boot-script size guard; this revision keeps the adapter in the application bundle without relaxing that guard. Check the latest CI result before approval. Hosted verification — deployment, real-browser consent, the first accepted payload and withdrawal — is still outstanding and cannot be closed from local checks.

Keep the existing primary/fallback roles. Never send answers, save data, imported puzzles, personal text or workshop contents. Baseline active signals are opted-in page views and content-free error occurrence counts. The registered puzzle start/completion/hint names are contracts awaiting explicit engine hooks, not yet complete genre funnels. Completion must come from validated puzzle success, not from a button click.
