# Roadmap

## Browser launch: 0.3

- Public repository and incremental import history.
- Original illustrated casebook cabinet, readable phone controls and keyboard entry to every board.
- Board-based deductions for Sudoku, Futoshiki, Sun & moon and Picture logic.
- Reopenable completed-record explanations.
- Save validation and recovery repairs, automated real-origin acceptance and CI.
- Public HTTPS deployment, reproducible release assets and documented agent workflow.

## Bellweather expedition: 0.4

- Four new original illustrations carried into case files and playing screens.
- Six coherent Bellweather records with timed chapters, cast and earned revelations.
- Tidal bridges: eight curated maps, an original bounded engine, lesson and visible-count hints.
- Independent rule oracle and real mobile-origin completion of the new catalogue.

## Next: player-calibrated content

Human-playtest two puzzles per family; record ambiguous instructions and actual solve times.
Curate the Briar House anthology with consistent locations, roles, objects and chapter recaps.
Publish revised definitions deliberately while preserving unfinished earlier revisions. Add richer
clue-based deductions only where they can be explained and tested without consulting solutions.

## Authoring, after evidence of use

Draft history and portable unfinished-draft export; ambiguity comparison and clue consistency
inspection. Keep local authoring distinct from public publishing. Split the large app controller at
these real boundaries as features grow, retaining the pure engines and save contracts.

## Android, then optional services

Complete the physical-device checklist in docs/ANDROID.md before store packaging. Add accounts or
sync only if player needs justify a backend; retain guest/offline play and explicit conflicts.
Payments, telemetry, remote player data and store release each require a separate scope and tier review.
