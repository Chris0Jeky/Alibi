## Order of work

The owner should evaluate the castle loop before implementing an economy around it. Then do the receipt contract. Blender asset preparation can proceed independently, but runtime ownership must use the reviewed contract. Build one companion role and one small reward kit before broadening the catalogue. Garden and city content consume the same entitlement boundary; they should not each invent a reward ledger.

Preserve current cat, fox, owl and Nimbus identities, names and progress. The existing six garden species and existing building capabilities stay usable. New story rewards add new choices. The current builder's existing larger layouts are not repackaged as locked rewards.

A personal town and the authored estate are different worlds. Finishing a chapter can restore the estate illustration and grant an optional model kit, but must not overwrite the user's town. Similarly, a memorial planting in the story does not forcibly replace the user's own garden.

## Suggested first reward collection

A deliberately small “Under the Dome” collection could contain one telescope model, one brass-and-indigo material set, one botanically reviewed seed option and one owl accessory. All four refer to the same discovered place. This is a more coherent test than twenty unrelated drops. Names and art remain proposals, not shipped entitlements.

The player should see where an item came from, whether it is already owned and where it can be used. Grant once, deliver a small readable receipt, and let the player dismiss it. Reopening the app must not replay a backlog of unskippable celebrations.
