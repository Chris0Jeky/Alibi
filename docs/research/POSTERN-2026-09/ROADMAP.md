## Following waves

**Make one excellent case reusable.** Add a Chapter I authoring adapter without changing published clues; resolve Chapter II proof gaps under #53; create a reviewed counterexample model; run first-visit human testing under #56. Promote only when semantic, editorial and lifecycle evidence agree.

**Broaden the kinds of discovery.** Prototype one interval/timeline mystery, one original symbol-language problem and one overlay/map reconstruction. Reuse cabinet reducers where they genuinely model the problem. Do not force every mystery into a grid or build three new engines before testing the first.

**Make return visits and authorship coherent.** Continue #219/#220 token consolidation, #51 notebook expansion, #433 discoverable optional collections and #55 method/familiarity tracks. Add creator diagnostics, spoiler-safe sharing and an explicit local playtest export. These should share contracts, not databases.

**Explore social and spatial bets.** Compare solo against two-dossier co-op; prototype a mechanical instrument with semantic controls; test an optional low-cost atmosphere layer. A server, camera, AR or WebGPU dependency follows demonstrated need, not an ambition checklist.

## Experiments with stop rules

1. **Citation-based case:** can participants explain the uncertainty without guessing classifications? Stop expanding the case if the source task is bookkeeping rather than reasoning. Revise wording or interaction before adding scenes.
2. **Two dossiers:** compare a shared sheet and split information using the same puzzle. Proceed to networking only if splitting creates useful explanation rather than reading aloud without deduction.
3. **Symbol grammar:** after a small teaching set, test an unseen construction. Reject the design if success depends on outside vocabulary or opaque cultural assumptions.
4. **Adaptive hinting:** offer an optional next-method prompt after explicit request; compare comprehension and regret. Do not infer distress or silently solve from elapsed time alone.
5. **Atmosphere budget:** compare static baseline with a bounded enhancement on the same device. Remove effects that obscure clues, slow input, increase fatigue or require a permission without a new mechanic.
6. **Creator editor:** observe an author fix a broken reference and hidden prerequisite. Build visual authoring only when a source-based workflow's concrete friction is known.

## Issue quality and concurrency

A child issue needs a player/author outcome, exact existing seam, evidence source or labelled hypothesis, dependencies, negative cases, acceptance, non-goals and stop rule. Do not open an issue per adjective or create a duplicate of a still-active owner. Use links to existing work and focused sub-slices.

Documentation, isolated authoring tooling and the build-only identity fix can progress independently. Case UI depends on the validator. Canonical Wrenmere content, storage adapters and reward integration must not be edited by overlapping writers. CI and independent review refer to the final head, not a predecessor. No self-modifying publication workflows, protection bypasses or fake green checks.
