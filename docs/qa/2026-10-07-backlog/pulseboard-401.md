# Issue 401 — host all-off before Pulseboard startup

Evidence only, from this checkout on 2026-10-07. No host, SDK, build, or policy edit.

## Finding

The required hook is absent. Pinned `pulseboard-sdk` 3.3.1 has no in-memory channel a host can set before the SDK script runs so that `mount()` treats the visitor as decided all-off. The current `migrationFailed` path applies all-off only from `settle()`, which on the deferred web page runs after `mount()` has already started the region hint and `page.view`.

A stored v3 record is a pre-start channel, and the successful migration uses it. It requires `localStorage.setItem` to succeed. That is the path `migrationFailed` exists for when the write throws.

## Pin and public surface

`observatory.lock.json` pins `observatory/pulseboard.js` at SDK `3.3.1`, SHA-256 `ab1921f0950a4164a31a00c7810d09569ece2eca7ef98474aa11ff96791deadc`. The file header says it was generated by Pulseboard `observatory/adapters/build-sdk.mjs` for `alibi` and must not be edited. Body SHA-256 in that header: `e2b62b11f9c5eb2ffcae9dc5c196f5f94cf980ee7977378426637bef634ccea6`.

The IIFE assigns a frozen `globalThis.Pulseboard` with only `version`, `route`, `count`, `track`, and `consent`. `consent` has only `get`, `set`, and `open` (`observatory/pulseboard.js` around the freeze at the bottom of the file). `mount` is not exported. `createPulseboard` reads, before `mount()`:

- `localStorage` key `pulseboard:consent:v3:` + project id (`readChoice`)
- `sessionStorage` key `pulseboard:region:` + project id (values `eea` or `other` only)
- at `mount()`, `<html data-pulseboard-route>` (a registered route name), `[data-pulseboard-bar]`, `[data-pulseboard-slot]`, and later `[data-pulseboard-scroll]`

A source scan of the artifact found none of: `preConsent`, `beforeMount`, `beforeStart`, `hostChoice`, `initialChoice`, `presetConsent`, `onBefore`, `ALIBI_`, `data-pulseboard-consent`, `data-pulseboard-off`, `pulseboard:pre`.

`consent.set` can hold an all-off choice in memory when `localStorage.setItem` throws (`decide`: storage success clears `memoryChoice`; failure keeps `memoryChoice`). The generated script publishes `Pulseboard` and, when `document.readyState !== 'loading'`, calls `mount()` in the same synchronous turn. Host code cannot call `consent.set` between those two steps.

## Web startup order

`tools/build.cjs` puts `src/pulseboard-host.js` in the application bundle and emits `observatory/pulseboard.js` verbatim as `assets/pulseboard.<hash>.js`. The web index loads these deferred scripts, in order: boot, identity, platform, official content, the application bundle, the block-motion loader, then the SDK. `observatory/check.local.mjs` requires that SDK script to be the last deferred script.

Deferred scripts run after `readyState` is `interactive` and before `DOMContentLoaded`.

1. Host script (`src/pulseboard-host.js`). If a legacy `pulseboard:statistics:v1:alibi` or `pulseboard:consent:v1:alibi:` value has `allow: false` and the v3 key is absent, it tries to write `pulseboard:consent:v3:alibi` as `{counts:false, diagnostics:false, journeys:false, decided:true, month}`. On `setItem` throw it sets `migrationFailed` and leaves the legacy key. It sets `<html data-pulseboard-route>` from the hash. `readyState` is not `complete`, so it does not call `settle`. It registers `settle` on `DOMContentLoaded` and `load`. `window.Pulseboard` does not exist yet, so `consent.set` cannot run here.
2. SDK script. `createPulseboard` reads storage. With no v3 record, `effective()` is the region default: counts on, diagnostics and journeys off while region is unknown; all three on when the session region is `other`. `readyState` is not `loading`, so `mount()` runs before the script returns.
3. Inside `mount()`, when not blocked: if there is no decided choice, the Beta notice is built. Then `startDiagnostics()`, `fetchRegion()`, `pageView()`. `fetchRegion()` returns immediately when a choice is already decided, a region is cached, or the browser is blocked. Otherwise it issues `GET {collector}/v1/consent/{id}` (5s abort timer). `pageView()` counts `page.view` when counts are on and enqueues a journeys `page.view` when journeys are on. The counts flush timer is `FLUSH_MS` (2000). One event does not flush immediately (`COUNT_BATCH` is 20).
4. `DOMContentLoaded`. Host `settle` runs. If `migrationFailed`, it calls `Pulseboard.consent.set({counts:false, diagnostics:false, journeys:false})`. `decide` marks that choice decided. `refresh` withdraws categories that turned off, which drops a still-queued `page.view`. The region `fetch` controller is local to `fetchRegion` and is not aborted by `consent.set`.

## Probe of that order (not a committed test)

One vm run of the current host source, then the pinned artifact, on the registered HTTPS origin, `readyState: 'interactive'`, legacy `{"allow":false}`, `setItem` throwing `QuotaExceededError`. Before `DOMContentLoaded`:

- `Pulseboard` was still undefined after the host.
- After the SDK script: `consent.get()` was `{counts:true, diagnostics:false, journeys:false, decided:false, region:'unknown', blocked:false}`.
- `fetch` had already been called with `https://pulseboard-observatory.commit-atlas.workers.dev/v1/consent/alibi`.
- Timers recorded were `5000` then `2000` (`fetchRegion` abort, then the `page.view` flush).
- The notice child `pb-bar` was already in `[data-pulseboard-bar]`.
- One `DOMContentLoaded` listener existed (the host). The SDK had not registered one.

Firing that listener then made `consent.get()` decided all-off and removed the notice. The region URL stayed in the fetch list.

The same harness with `setItem` succeeding wrote the v3 all-off record and removed the legacy key before the SDK script. After the SDK script, and still before `DOMContentLoaded`: decided all-off, no fetch, no timer, no notice. `settle` did not need `consent.set`.

## Prerequisite to finish 401

1. Upstream Pulseboard (`observatory.lock.json` `source`: `Chris0Jeky/Pulseboard:observatory`) adds a hook that `createPulseboard` / `mount` reads before `startDiagnostics()`, `fetchRegion()`, and `pageView()`. The host must be able to plant it during the earlier deferred application script, without `localStorage.setItem`. A read at `mount` that sets the same decided all-off `memoryChoice` `decide` already uses when storage refuses is enough for this fallback: `decided()` then skips the region GET, and `page.view` is not admitted. Putting the hook only on the `Pulseboard` object is not enough, because `mount()` runs in the same turn the object is published whenever `readyState !== 'loading'`.
2. Rebuild the `alibi` artifact with `observatory/adapters/build-sdk.mjs`, replace `observatory/pulseboard.js` with that output, and pin the new SDK version and SHA-256 in `observatory.lock.json`. The checked-in file is generated; editing it by hand breaks `observatory/check.mjs`.
3. After that pin is in this repo, `src/pulseboard-host.js` can publish the hook when `migrationFailed` is set, still before the SDK script. `settle`'s `consent.set` cannot be moved earlier while the artifact mounts synchronously.

Out of scope for that fix, and not a substitute: removing the SDK, or changing decided-choice wins, region defaults, GPC/DNT `blocked()`, notice OK/Choose, or re-enable through `consent.set`.
