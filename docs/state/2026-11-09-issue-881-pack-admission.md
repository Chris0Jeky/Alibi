# Issue 881: Legacy pack admission guidance

## Scope and outcome

Keep existing validated backups restorable even when their combined local puzzle count is above the 3,000-puzzle import limit. The Workbench shows exact total and custom-puzzle counts and a conditional notice when the current total is over the limit. The notice sits inside `#pack-list`, so the existing `pack-added` and `pack-removed` refresh replaces the count and notice together. Restore previews with custom packs state that oversized restores remain possible and give export/removal guidance without predicting whether that particular backup crosses the limit. Neither restore mode is blocked, and storage admission behavior is unchanged.

- Focused Node suite: 102 passed across `pack-admission-ui.test.cjs`, `app-backup-import.test.mjs`, `backup-route-race.test.cjs`, and `storage-restore.test.cjs`.
- The restore regression validates and restores 21 packs containing 3,150 puzzles.
- The UI tests execute the actual `packDesk()`, `syncPacks()`, and `importBackup()` source to check current counts, add/remove refresh, restore policy copy, and unchanged restore actions.
- `node --check src/app.js` and `git diff --check` passed.
- Composed/minified app comparison against `8a5e244`: 152,393 → 152,577 raw bytes (+184); gzip 50,311 → 50,429 bytes (+118). This is a focused `esbuild` composition measurement, not a production build.
