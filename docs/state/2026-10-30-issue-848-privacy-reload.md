# Issue 848 slice: privacy chunk recovery and failure-path test

Branch `claude/privacy-reload-848`, based on origin/main `278a5781`. Implements #848.

## Changed

- `src/app.js` `privacyPage()`: the failed state now shows `Retry` and `Reload Alibi` together in a
  `row actions` container. `Reload Alibi` reuses the existing `reload` action (`location.reload()`,
  as in the restore dialog) and the same `secondary` button style, so a tab whose hashed
  `privacy.<hash>.js` was purged by a later deploy can recover.
- `tests/browser_boot.py`: new `check_privacy_recovery`. On a fresh page it aborts
  `**/assets/privacy.*.js`, opens `#/privacy`, asserts the alert, the `Retry` and `Reload Alibi`
  buttons, unroutes, clicks Retry, then waits for `.privacy-copy h2` and `#usage-sharing-slot`.
  The named-route cases now also require the loaded `.privacy-copy h2` after reaching Privacy &
  credits (the h1 is shared with the loading and failed placeholders). Check count 6 -> 7.
- `tests/browser_ui.py`: the layout loop waits for `.privacy-copy h2` on the privacy route instead of
  relying on the fixed 80 ms in `route()`.
- `tests/budget.test.cjs`: precached shell ceiling +64 (documented in the existing style).
- `assets-source/library/catalogue.json`: regenerated by `node tools/assets/catalogue.cjs`.

Why the failure case is in `browser_boot.py` and not `browser_ui.py`: `browser_ui.py` loads the
standalone `alibi-deluxe-play.html` with `set_content`, where the privacy copy is inlined, so there
is no chunk request to abort. `browser_boot.py` serves the real `dist` over HTTP, already uses
route-abort for the main bundle, and is already wired into `.github/workflows/check.yml`.

## Residual risk

- Startup gzip has 10 bytes of headroom and the shell 44 bytes: the next startup change needs its
  own documented raise.
- If a purged chunk is also absent from the reloaded shell (a broken deploy), Reload shows the same
  failed state; that is a deploy problem, not covered here.
- A first `npm run build:android` in this worktree failed with a stack trace and passed on every
  rerun; the cause was not captured. Running `node --test` without `--test-concurrency=2` produces
  spurious "clean source tree" failures in the Android build tests (they share the checkout).
