# Issue #911: built-origin startup measurement

This adds a manually dispatchable and narrowly PR-triggered Chromium measurement, not a new
performance gate. It builds the unchanged web application, creates fresh disposable profiles,
seeds synthetic published Sudoku and Futoshiki runs into real IndexedDB on the local built origin, and records
three raw trials each for 0, 50 and 100 runs with empty histories, and 50 and 100 runs with
20 undo plus 20 redo entries. The history entries are independent states generated by real pencil
reducer edits across cells and candidates; a causal test checks undo/current/redo ordering and
state diversity. Each complete run passes the same pure validator used by startup. The seed receipt
checks stored keys and every history length; application diagnostics must report IndexedDB, the
expected restored-record count and zero quarantined records. Diagnostics is assigned only after
startup's normal validation loop and initial route load. Navigation/load timing, task entries starting
before readiness, unthrottled CPU rate, browser/OS/CPU, source commit/tree, build identity, file
hashes and every observation are retained in the workflow JSON artifact. Case order rotates each
round. Before the timed trials, HTTP preflight verifies the served index and its startup assets against
the built files; every trial also checks the runtime build and platform identity. The manifest visit
establishes the origin before seeding, and the preflight warms server and OS caches. These are
fresh-profile app navigations, not cold OS/network or established service-worker-cache measurements.

No production path, budget, save format, validation, or published identity is changed. The series
has no timing assertion; machine variability and three observations limit comparisons. It contains
synthetic data only and does not establish phone performance. The 200-entry history boundary is
not included in the timed series; the 40-entry profile is the requested realistic-depth sample.

Local checks: fixture generator validates all six count/history combinations; the causal fixture
test, Python compilation, and formatter checks pass. A local HTTP preflight verified ten startup
files and rejected an intentionally mismatched index hash. Chromium execution is pending CI: the local environment lacks its browser,
and the prior official download returned a SiteUnavailable response. The workflow needs a real
successful run and artifact review before drawing any timing conclusion. No hosted origin or
physical device was accessed. Existing HUMAN_TODO owner decisions remain open.
