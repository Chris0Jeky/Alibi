# UX flow and Castle accessibility pass (2026-11-09)

## Changed

- **Phone completion layout.** After a solve, the in-page "That satisfying aha" card (Another puzzle, Review the record, Back to collection) now follows the board on phones (CSS `order` in the 650px block) instead of sitting below Restart/How to play/Report. Measured 390x844 on a 4x4 Sudoku: the card started near y=1000 before and near y=860 after. It remains just below the fold; the completion dialog stays the primary prompt.
- **Another puzzle on a finished family.** `nextPuzzle` opened an already-solved puzzle when every puzzle in the family was solved (`pickNext` wraps to the first). It now opens the family list.
- **Family rules card on phones.** `.family-intro p` had `flex: 1` so the rules text was squeezed beside the Learn to play button. It now wraps the button below (`flex: 1 1 14em`).
- **#219.** The hero h2 is already smaller than h1 on the desk; two other desk h2 (Stay for the atmosphere 43.5px, A table by the window 38.4px) exceeded h1 (36px). Both are capped at `--text-h1` (36px desktop, 32px phone).
- **Castle case.** Source checkboxes sit in a labelled group; a missing verdict is `aria-invalid` after a failed check; the global `main:focus{outline:none}` is removed so programmatic focus shows the keyboard ring.

## Not done

- Eclipse Lab items (role, focus outline, contrast) were skipped by instruction: another worker owns `src/eclipse-lab/**`.
- Castle case: the player sits at 16,447 bytes against a 16,448 ceiling (was 16,409). Fitting the group and the invalid flag required deleting two shell-duplicated rules (`.actions` wrap, select sizing) and one helper. Missing-citation errors are not flagged per field and the stage error is not `aria-describedby`-linked; the live status region announces it. More needs a ceiling decision, not an agent edit.
- Not changed: the completion dialog still offers only Another puzzle and Review the record; adding a family-list action costs startup JS.
