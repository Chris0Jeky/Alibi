# Pack validator deduplication and bundle headroom

The core-only and additional-engine pack validators shared header, pack-size, puzzle-ID,
uniqueness and output construction but shipped both copies in the application and validation
worker. Core now owns that shared construction; the additional-engine wrapper supplies the
extended definition/solver dispatch and preserves its existing error messages. Core-only calls
still use the original core definition/solver behavior and original messages. Pack shape,
limits, source cloning, unknown-type refusal, solver checks and stored data are unchanged.

The source tree began at `cd2a290829f88c75ebd4523803ee73d713b99cd1`, matching GitHub main
`8730ac4c3c369646a943929f81610c8c4b5de59a`. The local checkout uses a synthetic commit of
that tree and an ignored dependency link; it is not the GitHub commit.

The alternative of switching the application transform to UTF-8 emission lowered raw size in
a composition probe but increased gzip size, so it was rejected. Moving gameplay into a new
chunk, raising budgets, and removing core-only validation were not pursued.

## Evidence and remaining gates

`tests/pack-validator-equivalence.test.cjs` runs the core-only validator captured before the
engine layer and the extended validator afterward. It checks distinct exact diagnostics,
valid original and additional-engine packs, input preservation and detached output, and both
uniqueness solver dispatches. The same cases pass on the original and candidate code. Existing
pack-cap, core and official-catalogue suites also pass locally. Independent VM comparison of
each of the 116 puzzles in `content/catalog.json` through both validator modes gave 232 identical
results, including the core-only rejections of extra types. A late-registration regression
captures the extended validator before loading Bridges, then proves it resolves Bridges after
registration while the captured core-only validator still rejects it; it passes on both versions.

A fresh clean source tree `10868abc09112b87f8e5d98376b337a2f77d81cf`, synthetic commit
`7539a613e6779d81e5da99e6dfa9a682b40381`, built the web and Android payload with
`sourceDirty: false`. Application gzip measured 135,266 bytes against 135,776 on the local
baseline (−510); initial code/content measured 204,492 against 205,002 (−510). Accounted net
shell and core offline bytes were 1,408,962 and 1,926,581, each 1,090 below the local baseline.
The baseline source tree matched main, but its ignored dependency symlink had not yet been
excluded from Git, so that baseline reported `sourceDirty: true`; identity differences can
change unrelated generated bytes. Hosted main reported application gzip 135,776 and net
shell 1,410,053, consistent with the reported savings to within one shell byte.
The earlier reused checkout failed `Unexpected existing platform identity`; this successful
build used a new checkout without generated artifacts or any guard modification. The full
`npm run verify` in that fresh checkout passed: formatting and Android payload build, 2,173
Node tests with zero failures or skips, 581,856 Quiet Wing engine assertions and 123 adapter
contract assertions. The late Bridges test and this evidence text were added afterward; the
application source remained identical and the added test separately passed on old and new code.

No budget, app UI, database or save authority changed. Hosted full/browser/offline checks and
independent review are still necessary. Physical-device and owner acceptance remains in
